# Brevia 设计语言

更新日期：2026-10-12。适用范围：Electron 桌面应用与 Flutter 手机应用。

这份文档定义当前界面的语义和基础规则；页面构图见[设计风格](design-style.md)，代码现状及接手顺序见[前端 UI 重构进度](frontend-ui-refactor-progress.md)。设计图的功能校准和特殊组件尺寸以[完整规范](redesign-2026-10-12/design-specification.md)为准。

## 设计原则

界面应像一份清晰的会议文档：导航负责找到会议，正文负责阅读和整理，控制条负责采集。参考 yovoice 的简洁工作台语法，采用白底、浅灰导航、细线分区和黑色主操作。

- 信息层级靠字号、字重、对齐、间距和分隔线表达。
- 中性色承载界面；颜色只表达录音、成功、等待、危险等真实状态。
- 控件样式可以更新，业务动作、下载队列、通信协议和持久化值继续使用既有实现。
- 设计图中的模型、会议、日期、容量、配对码和百分比都是示例，真实内容读取接口。
- 已覆盖的页面与状态遵循同一套组件；新增或尚未覆盖的状态先补设计图，再实现。

桌面令牌位于 [tailwind.css](../frontend/tailwind.css) 的 `@theme` 和 `html[data-theme="dark"]`；页面布局使用 [design-layout.css](../frontend/design-layout.css)。手机由 [breviaTheme](../mobile/lib/design_system.dart) 映射到 Flutter 的 `ColorScheme` 和控件主题。

桌面录音提示另有 `--color-recording`：浅色 #FF0000、深色 #FF6B6B。提示同时显示状态文本，不能只靠红点表达。手机结束按钮使用主题的错误色。部分桌面文字令牌与目标色板仍存在取值差异，接手时按[进度中的校准项](frontend-ui-refactor-progress.md#待完成的验收与整理)核对，不能假定两端每个色值已完全相同。

## 尺寸与比例

桌面源画布为 **1440×900**，默认应用窗口为 **1280×800**。窗口与内容统一按 **8/9，约 88.9%** 显示。下文桌面数字均为源画布单位，不是缩放后的屏幕显示尺寸。

| 项目         | 源尺寸  | 默认显示尺寸约值 |
| ------------ | ------- | ---------------- |
| 常规侧栏     | 272px   | 242px            |
| 实时收起侧栏 | 64px    | 57px             |
| 标准图标     | 24px    | 21.3px           |
| 正文基准     | 16px    | 14.2px           |
| 通用按钮     | 44px    | 39.1px           |
| 通用字段     | 48px    | 42.7px           |
| 页面内边距   | 32–40px | 28.4–35.6px      |

默认窗口同时受显示器可用区域限制，最小窗口约束为 880×640。继续调整窗口大小时使用已有响应式布局，不追加随窗口缩小的字体压缩。原生标题栏按系统尺寸呈现。

缩放唯一入口是 [electron/main.js](../electron/main.js) 的 `createWindow()`：`webPreferences.zoomFactor: 1280 / 1440`。不要再给页面叠加 CSS `zoom` 或整体 `transform: scale()`，也不要逐页把像素值重复乘以 8/9。仅在加载前调用 `setZoomFactor()` 会在重载后失效，已由真实 E2E 检查覆盖。

手机参考 iOS 390×844、Android 412×915，验证下限为 360 宽。手机遵循系统文字大小和安全区，不使用桌面缩放。

## 字体与阅读

桌面使用系统无衬线栈：`-apple-system / SF Pro Text / Helvetica Neue / PingFang SC / Microsoft YaHei / Arial / sans-serif`。手机 iOS 使用 SF Pro Text，其他平台使用 Roboto 及系统回退。

| 层级       | 桌面源尺寸          | 手机逻辑尺寸           |
| ---------- | ------------------- | ---------------------- |
| 页面标题   | 28–32px，字重 600   | 主页面按场景使用 28–32 |
| 二级页顶栏 | 按页面标题体系      | 18，字重 600           |
| 区块标题   | 18–20px，字重 600   | 20，字重 600           |
| 阅读正文   | 16–18px，行高约 1.6 | 18，行高约 1.65        |
| 普通控件   | 14–16px             | 16–17                  |
| 辅助信息   | 13–14px             | 14                     |

品牌和引导主标题有独立层级，具体值见对应页面与完整规范。正文对比度目标为 4.5:1；停用控件要明确表现为不可操作。时间、进度使用可比较的数字排列。系统大字下让行高和内容区增长、滚动，避免裁掉操作按钮。

## 组件语法

- 间距基准：4 / 8 / 12 / 16 / 24 / 32 / 48。同一组内紧凑，组与组之间拉开。
- 控件圆角 8px，桌面弹层 12px，手机底部弹层 16px。任务卡片使用细边和 8px 圆角。
- 主按钮深底浅字；次按钮透明或白底细边；危险操作红色文字或危险色按钮。悬停、按下、停用、忙碌、失败均须有可辨别的反馈。
- 输入标签位于字段上方，错误就地显示，失败后保留用户输入。不要为样式改动更换提交字段或保存值。
- 桌面通用图标由 [interfaceIcon](../frontend/ui-components.js) 提供：24px 画框、1.6px 线宽、`currentColor`。小型操作可使用已有同风格 SVG。
- 手机使用既有 Material 图标体系，常用操作选线框图标；录音条使用暂停/播放、书签、停止。
- 图标按钮提供可访问名称。手机触控区至少 48×48，录音控件当前为 56×56。纯图标录音按钮不额外加文字标签。
- 页面和列表以分隔线组织，不用厚阴影。菜单允许轻微层级阴影，普通内容面保持平坦。

## 状态与操作语义

会议来源、采集状态、上传状态、转写状态必须分开表达。“手机录音”是来源标识，不能拿它判断设备是否在线；“本地已保存”不能等同于“已上传”。

实时会议只显示时间戳和转写正文，**不显示说话人姓名、头像或人数识别结果**。会后精修的说话人功能继续保留，不能把实时隐藏规则扩散到会后页面。

录音、静音、断线、系统中断和保存失败是不同状态。断线但本地仍在采集时应表达录音继续；中断时保留已保存时长并提供恢复操作。重试不能丢失录音或编辑草稿。

确认弹窗写清对象和后果，默认聚焦取消。受保护配置弹窗约束焦点，关闭后恢复背景交互和原焦点。普通设置使用连续页面。

任务卡片显示真实任务进度，不生成虚假百分比；最小化、暂停、关闭各有独立含义，具体关闭行为沿用每类任务的业务处理。

## 国际化与产品边界

桌面语言选择完整保留 zh / en / es / ja / ko / fr / de / ru 八种语言；手机另有“跟随系统”。所有新增文案同步进入各端现有词条系统，不硬编码中文标题。

模型引导选择具体模型进行多选下载，平台过滤、推荐、已安装状态和容量均使用现有清单。不把下载改成“实时识别 / 精修 / 说话人识别”三个能力包。

AI 纪要与智能笔记独立开关、独立配置。智能笔记的 quiet / assist / auto 使用原有值；关闭功能由开关决定。在线服务说明准确表达“相关文字按设置发送至所选服务商”。

手机负责采集、保存、传输和回看；电脑负责 AI 推理。Android 安装二维码打开真实 APK 下载地址，iPhone 使用受邀 TestFlight 安装。安装二维码与短期设备配对二维码分别呈现，不把画板示意二维码放进应用。
