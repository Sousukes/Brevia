本轮定向更新 **D04、D05、D07、D08、D13–D19、D25、D27、D36**，新增 **D14a、D14b、D37–D41**。其余画板只做等比例尺寸归一化，保留原构图、元素与文案；其历史壳层不代表另一套公共组件方案，接手时统一套用下述侧栏、窗口栏与文案约定。D10 保留阅读布局，编辑状态由 D37/D38 补充；D24 保留任务类型示意，任务实际位置以 D25 为准。

## 公共组件与文案

### 应用侧栏与窗口栏

桌面应用按 **1280×800 CSS 像素、100% 显示**接手。主侧栏 224px，窗口栏 40px；内容内边距 24–32px。这些是实施尺寸，图片中的模拟窗口边框、留白和生成误差不能当作 CSS 测量值。D05 是应用壳层基准，引导页沿用自己的品牌/步骤栏，不套用会议导航。

| 区域       | 固定顺序与位置                                       | 文案与行为                                                                   |
| ---------- | ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| 侧栏上部   | 品牌 → 开始会议 → 导入本地音频 → 会议库 → 最近删除   | “开始会议”是入口，“新建会议”是准备页标题，“开始录制”是提交按钮，三个用途固定 |
| 工作区     | 导航分隔线下；标题左对齐、右侧小“＋”；下方工作区列表 | “＋”名称为“新建工作区”，有焦点与悬停说明；创建、编辑、删除复用 D34           |
| 侧栏下部   | 工作区滚动区 → 任务堆叠 → 设备连接 → 设置            | 设备状态与名称分开，设备连接、设置入口始终可见                               |
| 窗口栏右侧 | 当前版本 → GitHub 图标 → 语言图标“文” → 外观图标     | 版本来自应用；GitHub 指向现有仓库；外观图标有“切换主题”名称与提示            |
| 外观       | 所有页面同一位置与图标体系                           | 浅色/深色/跟随系统仍是现有三个值；主题变化保持布局                           |
| 删除入口   | 主导航中会议库相邻位置                               | 统一“最近删除”，不另加一个同义“回收站”入口                                   |

图标采用同一套 1.5–1.75px 线宽、20–24px 视觉尺寸；手机来源用细线设备矩形。工作区、设备和主题不能在不同图中换一套图标。版本号示例统一 v1.3.1；GitHub 使用现有 `zerolovesea/Brevia` 仓库，不新增社交入口。

### 设置页面

所有设置固定使用 **224px 主侧栏＋200px 设置导航＋右侧内容**。二级导航依次为：**通用、模型库、AI 功能、进阶设置、声纹管理、设备连接、存储与隐私、关于与更新**。切换时仅更新选中项、标题与内容；两栏不重新布局，不整窗缩放。

D13 的通用页只呈现界面语言与外观；其他设置使用相同标题起点、字段样式、分隔线和页内滚动容器。长表单底部操作条保留可见空间。D19 只呈现存储与隐私，关于与更新移至已有导航对应的 D41。会议内与引导中的服务配置仍用原有模态窗口，不把全部配置改成页面。

页面标题 30px、阅读正文 16–17px、控件 14–16px、辅助文字 13–14px；按钮高 40–44px、字段 44–48px、圆角 8px、弹层圆角 12px。颜色、字体、间距、安全区与平台限制继续采用[设计规范](design-specification.md)。

### 编辑窗口与保存状态

D37 与 D38 使用同一会议详情壳层，左侧笔记、右侧会议纪要、底部播放条均保留位置。编辑是原页面内的状态，不打开一个不同风格的新窗口。实时笔记与会后编辑复用同一编辑器视觉组件。

工具栏顺序沿用现有编辑器：加粗、斜体、H1/H2/H3、列表、编号列表、引用、链接、图片、表格、行内代码、待办、重点、模式切换。富文本直接展示排版；Markdown 展示等宽源码，不再新增双栏预览。模式切换保持同一草稿，不能显示为不同内容或不同已保存状态。

Markdown 中沿用实际的命令可用性：依赖富文本选区的格式命令禁用；表格、待办、重点及模式切换仍按现有实现处理。模式图标是同一个切换按钮，画板的文字用于标识当前模式，不代表新增多个菜单入口。取消与保存图标位于内容标签行右侧，读屏名称分别为“取消”“保存”，悬停提示明确。

| 状态                       | 显示                              | 操作与边界                                       |
| -------------------------- | --------------------------------- | ------------------------------------------------ |
| 未进入编辑                 | “已保存”＋勾号，可附最后保存时间  | 提供编辑入口，不把 AI 输出标作人工确认           |
| 草稿已修改                 | “已修改 · 尚未保存”＋中性状态标识 | 保存和取消；切换模式不丢草稿                     |
| 保存请求进行中             | “正在保存…”＋忙碌图标             | 防止重复提交，尚不能显示成功                     |
| 保存成功                   | “已保存”＋勾号/实际时间           | 必须等待实际写入成功；临时成功消息与持久状态分开 |
| 保存失败                   | “保存失败，修改仍保留”＋错误标识  | 保留编辑内容、允许重试；不清空草稿               |
| 实时笔记                   | 沿用自动保存，状态样式共用        | 仍以实际保存结果驱动，不改变现有保存方式         |
| 会后笔记、字幕、纪要及配置 | 沿用各自手动保存动作              | “已修改”属于当前内容区，不作为整应用的统一状态   |

D39 是状态组件示意，不是新任务页面；D15/D16 的状态提示用于配置草稿。AI 纪要保留“AI 生成，请核对。”，保存不等于核对完成。

### 任务堆叠

D25 将精修、迷你播放、迷你录音的三个并存状态放回主侧栏。卡片宽度不得超出侧栏内边距。前层显示状态、标题、真实进度与适用操作，后层保留约 40px 的可聚焦标题。当前任务不靠颜色单独区分；名称截断时提供完整提示。

设备连接和设置固定在底部，任务区向上占用空间，工作区列表缩短并独立滚动。实时侧栏收起为 72px 时仅保留任务指示，悬停或键盘进入后在同一位置恢复卡片；展开不能覆盖正文中的编辑保存按钮。D26 保留原收起/展开示意，公共位置继承 D25。

任务种类、暂停/继续、最小化/还原与关闭语义沿用现有逻辑：精修关闭取消任务，模型下载关闭只隐藏卡片；翻译不新增暂停；正在录音的任务不能因关闭展示而丢弃录音。D25 右下状态对照是评审标注，不能实现成覆盖会议库的额外浮层。

已安装页展示当前设备已有模型及随包组件；可下载页只展示未安装、可下载的模型。语音检测、说话人分离与声纹识别组件使用“随应用安装 / 必需”只读状态，没有移除或更新按钮。普通已安装模型沿用“从文件夹打开 / 移除”，未安装模型沿用下载、暂停/继续和错误重试；国内下载源入口保留。不增加本地模型导入或虚构“本地实时识别”模型。

评级统一使用 **标签＋档位文字＋连续短条**：质量 1/2/3 映射“标准/高/极高”，速度 1/2/3 映射“较慢/均衡/快”；56px 左右、4px 高的短条按 1/3、2/3、完整长度显示，浅灰底轨、深灰填充，不用旧三个点、星星或百分制。它是清单的相对档位，不是实时测试成绩。引导、模型库与 AI 配置读取同一组值，浅深色结构一致。

## D16 进阶设置的实际边界

字段来自[实际配置](../../backend/settings.json)、[字段文案](../../frontend/i18n-data.js)和 `settings.advanced.get` 元数据。权限置于表单前，随后九个可展开分组；字段保持原有数字/文本输入与单位，不把数值型 0/1 转成新的持久化布尔值，不新增“识别精度”或全局“识别语言”选项。

| 分组            | 必须覆盖的实际字段                                                                                              |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| 音频            | 采样率、音频分块时长                                                                                            |
| 识别与端点检测  | 精修窗口时长                                                                                                    |
| 实时识别        | 最大混音对齐延迟、整句识别段长上限、麦克风目标/最小响度、最大增益、峰值限制、安静语音兜底识别及生效时的相关参数 |
| 说话人分离      | 说话区间模型、聚类/在线匹配/声纹匹配阈值、最短声纹语音、边界回补、切换检测、固定人数、最短说话与静音间隔        |
| 会后精修        | 分块超时、最长精修时长、说话人分块/重叠、声纹窗口、自动聚类最多人数/最少窗口/最短语音/分数容差                  |
| 语音检测（VAD） | 默认（其他语言）与中文两组；各自阈值、最小静音、最短与最长语音时长                                              |
| 声纹库          | 每人最大录音条数、最大录音时长                                                                                  |
| 会议            | 删除记录保留天数                                                                                                |
| 纪要模型        | 模型请求超时                                                                                                    |

D16 展开示例为采样率 16000Hz、分块 30 秒、混音延迟 1500ms、段长上限 22 秒、目标响度 0.08、兜底识别 1；它们来自当前默认配置，运行值仍以接口返回为准。段长限制提示由 `speech_cap_minimum` 生成，字段可见性服从 `inactive_fields`：macOS MLX 不显示安静语音最短/最长时长及相对响度阈值。图片中的辅助说明不能引入新的参数范围、强制截句承诺或校验规则。

底部沿用“恢复默认 / 确定”；保存过程中保留输入，失败就地提示。通用、存储、AI 服务与会议语言设置不重复塞入进阶分组。

## AI 引导与演示的状态顺序

桌面引导顺序统一为 **语言 → 权限 → 模型与存储 → AI 功能 → 手机连接 → 功能演示**。D27 展示设置与预览，D40 展示状态分镜，D35 保留原五项功能演示导航。两种“步骤”分别属于引导流程和功能演示，不能混用编号。

| 模式          | 触发和演示顺序                                                     | 写入笔记的时机                     |
| ------------- | ------------------------------------------------------------------ | ---------------------------------- |
| 关闭          | 关闭对应开关 → 停止/清空该功能预览 → 说明未开启                    | 不写入，两个功能的开关独立         |
| 手动 `quiet`  | 点击请求 AI 建议 → 分析 → 展示建议与“加入笔记 / 忽略”              | 用户点击加入；忽略后笔记不变       |
| 适度 `assist` | 积累字幕、发现重点 → 展示建议 → 等待用户选择                       | 用户点击加入；补充类沿用“补充”动作 |
| 主动 `auto`   | 获取建议 → 用户输入时暂存 → 停笔后追加                             | 自动追加，无虚构“采纳 / 忽略”步骤  |
| 会后纪要      | 录音结束 → 发起纪要处理 → 左下任务卡显示阶段/进度 → 完成后显示文档 | 结果成功返回并保存后显示“已保存”   |

上述顺序依据[实时 AI 与引导实现](../../frontend/app.js)中的 `requestAiSuggestion`、`flushAutoSuggestions`、`appendAiSuggestion` 和纪要处理流程。演示可以使用固定样例与进度，但不能将示例时间承诺为模型处理耗时。建议不能提前显示为已确认笔记，主动模式也不能伪装成需要人工采纳。

建议出现/消失使用 120–180ms 短淡入；正式笔记在真实写入对应的状态点一次追加，用户正在输入时不移动光标。会后纪要由任务态转入结果态，不逐字打字、不无故闪回骨架、不把进度条放进正文。切换主动性重置该模式演示，关闭开关停止演示；降低动态效果时直接显示状态。引导预览是样例，不调用真实录音、模型请求或保存接口。本轮交付静态分镜与交互约定，应用动画实现单独验收。

## 使用限制

- 这些是静态设计图和状态分镜，不是可运行页面；imagegen 的中文、图标、局部尺寸仍可能有误差，准确功能和文案以本 README 与真实数据源为准。
- 示意二维码不能用于连接；状态、版本、容量、时间和进度不代表真实运行数据。
- 手机仍负责采集、保存、传输和回看，电脑负责 AI 推理；不新增手机模型、账号或订阅流程。
- iOS 系统状态示意不等于承诺已实现 Live Activity；Android 更新交互不能复用于 iOS。
- M02 的准备示意以 M15 的实际字段为准；M13 按真实三页手机引导校准。D30 为在线配置、D36 为本地配置，不新增导航或产品能力。
- 历史 `docs/mobile-design` 已从当前分支移除，仍可通过 Git 历史追溯。D21 历史草稿不参与有效图册验收。
