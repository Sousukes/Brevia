## 公共组件与文案

### 应用侧栏与窗口栏

桌面应用按 **1280×800 CSS 像素、100% 显示**接手。主侧栏 224px，窗口栏 40px；内容内边距 24–32px。这些是实施尺寸，图片中的模拟窗口边框、留白和生成误差不能当作 CSS 测量值。D05 是窗口栏与基础壳层基准；工作区与任务分区由第九轮 D25/D50 覆盖。其他未重画页面的常驻工作区长列表属于历史示意。引导页沿用自己的品牌/步骤栏，不套用会议导航。

| 区域       | 固定顺序与位置                                        | 文案与行为                                                                               |
| ---------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 侧栏上部   | 品牌 → 开始会议 → 导入本地音频 → 会议库 → 最近删除    | “开始会议”是入口，“新建会议”是准备页标题，“开始录制”是提交按钮，三个用途固定             |
| 工作区     | 导航分隔线下；标题左对齐、右侧小“＋”；下方单行选择器  | “＋”名称为“新建工作区”；下方只放当前工作区选择器，列表移至弹层；创建、编辑、删除复用 D34 |
| 侧栏下部   | 固定工作区选择器 → 独立任务区 → 设备连接 → 设置       | 设备状态与名称分开，设备连接、设置入口始终可见                                           |
| 窗口栏右侧 | 当前版本 → GitHub 图标 → 外观图标；语言仅在设置中切换 | 版本来自应用；GitHub 指向现有仓库；外观图标有“切换主题”名称与提示                        |
| 外观       | 所有页面同一位置与图标体系                            | 浅色/深色/跟随系统仍是现有三个值；主题变化保持布局                                       |
| 删除入口   | 主导航中会议库相邻位置                                | 统一“最近删除”，不另加一个同义“回收站”入口                                               |

图标采用同一套 1.5–1.75px 线宽、20–24px 视觉尺寸；手机来源用细线设备矩形。工作区、设备和主题不能在不同图中换一套图标。版本号示例统一 v1.3.1；GitHub 使用现有 `zerolovesea/Brevia` 仓库，不新增社交入口。

### 设置页面

所有设置固定使用 **224px 主侧栏＋200px 设置导航＋右侧内容**。二级导航依次为：**通用、模型库、AI 功能、进阶设置、声纹管理、设备连接、存储与隐私、关于与更新**。切换时仅更新选中项、标题与内容；两栏不重新布局，不整窗缩放。

D13 的通用页只呈现界面语言与外观；其他设置使用相同标题起点、字段样式、分隔线和页内滚动容器。长表单底部操作条保留可见空间。D19 只呈现存储与隐私，关于与更新移至已有导航对应的 D41。会议内与设置中的服务配置沿用原有模态窗口；引导 D27 的顶部直接配置已撤回；当前保留功能卡与独立共享配置入口，复用同一字段和条件。

页面标题 30px、阅读正文 16–17px、控件 14–16px、辅助文字 13–14px；按钮高 40–44px、字段 44–48px、圆角 8px、弹层圆角 12px。颜色、字体、间距、安全区与平台限制继续采用[设计规范](design-specification.md)。

### 编辑窗口与保存状态

D37 与 D38 使用同一会议详情壳层，左侧笔记、右侧会议纪要、底部播放条均保留位置。编辑是原页面内的状态，不打开一个不同风格的新窗口。实时笔记与会后编辑复用同一编辑器视觉组件。

工具栏顺序沿用现有编辑器：加粗、斜体、H1/H2/H3、列表、编号列表、引用、链接、图片、表格、行内代码、待办、重点、模式切换。富文本直接展示排版；Markdown 展示等宽源码，不再新增双栏预览。模式切换保持同一草稿，不能显示为不同内容或不同已保存状态。

Markdown 中沿用实际的命令可用性：依赖富文本选区的格式命令禁用；表格、待办、重点及模式切换仍按现有实现处理。模式图标是同一个切换按钮，画板的文字用于标识当前模式，不代表新增多个菜单入口。取消与保存图标位于内容标签行右侧，读屏名称分别为“取消”“保存”，悬停提示明确。

| 状态                       | 显示                              | 操作与边界                                       |
| -------------------------- | --------------------------------- | ------------------------------------------------ |
| 未进入编辑                 | “已保存”＋勾号，可附最后保存时间  | 提供编辑入口，不把 AI 输出标作人工确认           |
| 草稿已修改                 | “已修改 · 尚未保存”＋中性状态标识 | 保存和取消；切换模式不丢草稿                     |
| 保存请求进行中             | “正在保存…”＋忙碌图标             | 防止重复提交，尚不能显示成功                     |
| 保存成功                   | “已保存”＋勾号/实际时间           | 必须等待实际写入成功；临时成功消息与持久状态分开 |
| 保存失败                   | “保存失败，修改仍保留”＋错误标识  | 保留编辑内容、允许重试；不清空草稿               |
| 实时笔记                   | 沿用自动保存，状态样式共用        | 仍以实际保存结果驱动，不改变现有保存方式         |
| 会后笔记、字幕、纪要及配置 | 沿用各自手动保存动作              | “已修改”属于当前内容区，不作为整应用的统一状态   |

D39 是状态组件示意，不是新任务页面；D15/D16 的状态提示用于配置草稿。AI 纪要保留“AI 生成，请核对。”，保存不等于核对完成。

### 工作区与任务的空间分配（第九轮）

D25 的新版将常驻工作区长列表改为 **工作区标题＋当前工作区选择器**。主侧栏仍为 224px，工作区区域固定 100px，标题右侧保留新建工作区“＋”，下面只有 44px 高的当前名称/文件夹图标/下拉箭头。工作区数量、名称长度和搜索结果不能增加这块区域高度；长名称单行截断并提供完整提示。当前未分配工作区时显示“公开工作区”，不把“未分类”别名代替公开工作区。

D50 展示许多工作区与 6 个任务共存：点击选择器后，完整工作区列表以锚定弹层向侧栏右侧打开，不加入侧栏纵向布局。弹层顶部“搜索工作区”、底部“＋ 新建工作区”固定，中间真实工作区列表独立滚动；公开工作区置于列表起始，当前项显示勾号。弹层高度受窗口可用范围限制，不伸出窗口，也不覆盖任务卡片或底部入口。空间不足时翻转或向上对齐，不把工作区菜单画成一个推开任务的大抽屉。弹层临时遮盖部分会议行是正常浮层行为，会议分组和行间距不得为让菜单内容可见而重新排版。

| 区域           | 高度与滚动规则                                                | 保留的操作                                            |
| -------------- | ------------------------------------------------------------- | ----------------------------------------------------- |
| 品牌与主导航   | 沿用原有紧凑布局；固定可见入口                                | 开始会议、导入本地音频、会议库、最近删除              |
| 当前工作区     | 固定标题＋单行选择器；不滚动、不随工作区数量增长              | 切换当前工作区；“＋”复用 D34 新建表单                 |
| 工作区弹层     | 搜索与创建固定，只有列表滚动                                  | 实际名称、当前项勾号；编辑/删除仍复用 D34             |
| 任务标题与列表 | 位于选择器下方，独立取得剩余空间；标题显示“任务 · N”          | 收起/展开整个展示区，不暂停或取消任务                 |
| 任务卡片       | 标准 1280×800 下预留约 220–260px 任务视口；溢出只滚动任务列表 | 真实标题、进度和各任务现有暂停/继续、最小化、关闭操作 |
| 底部入口       | 固定设备连接＋设置，不属于任务滚动区                          | 设备状态、查看连接、设置始终可达                      |

D25 展示 3 个任务全部可见；D50 的第四张卡片露出标题并配合任务区滚动条提示还有任务，不能把卡片截断当作没有任务。卡片宽度不超出侧栏内边距，标题单行截断且保留完整提示，最小化后仍保留任务名称与适用控制。多项任务不在正文上叠成浮层，也不引入另一个任务中心。

任务属于整个应用，不随当前工作区筛选。切换工作区只改变会议列表，不能隐藏正在录制/下载/精修的任务、重置其进度或清空任务区滚动状态。工作区弹层打开和关闭时，任务区的位置、高度及可用操作不变；关闭菜单后焦点返回选择器。列表项支持原有工作区操作；会议移动仍用 D43 的目的地菜单，已有拖到工作区的能力需在选择器/弹层接手时保持可达，不更改分配接口。

任务超过视口高度时使用一个任务列表滚动容器，不让每张卡片各套一个滚动条。录制侧栏收起为 72px 时按 D51 保留单张任务汇总缩略卡，悬停或键盘进入后在同一侧栏恢复新布局；D26 保留历史收起/展开示意，其图标提示由 D51 的单张汇总缩略卡覆盖，工作区与任务空间规则由 D25/D50 覆盖。短窗口压缩卡片留白并允许任务区独立滚动，至少保留一个可操作任务标题；极端高度不足时主导航另设独立滚动，设备连接和设置不被挤出窗口。菜单和任务的焦点进入时应滚动当前项至可见。

没有任务时隐藏任务标题和卡片，剩余空间保留留白；工作区选择器不自动恢复为长列表，避免任务出现时重新跳动布局。新增任务保留正在操作卡片的焦点，不为腾空间自动关闭、取消或最小化已有任务；不要把任务视口高度与工作区列表项数绑在一起。

任务语义继续沿用现有逻辑：精修关闭取消任务，模型下载关闭仅隐藏卡片，翻译不新增暂停，正在录音不能因关闭展示而丢弃录音。原 D25 右下的最小化/暂停评审浮层已移除，相关状态继续参考 D24 和本 README；会议正文不承载任务评审注释。

第九轮是侧栏的新接手基准。历史图中的常驻工作区列表、此前“工作区与任务争抢侧栏高度”的还原和任务截图不表示此布局已经实施；新选择器及工作区弹层、标准/短窗口任务可达性需要重新核对。

### 收起侧栏的任务缩略图（第十一轮）

D51 重新设计为 **一个 52×44px 的汇总入口**，靠侧栏底部，紧贴固定设备连接/设置入口上方。72px 收起栏内左右各留 10px；这块区域不再另放“任务 · N”标题、任务类型图标、独立类型名称或装饰进度条。仅两行：第一行“任务”＋实际数量，第二行当前任务状态。图中是“任务 3”和录音状态点＋“18:42”，完整名称、各任务进度及操作仅在展开后显示。旧稿的 56×76px 卡片、三张小卡和居中位置均已弃用。

当前任务沿用已有激活项；没有激活项时沿用列表首项，完成后展示下一项，不自动轮播。录音和播放显示实际计时/位置；精修、纪要、翻译与下载显示实际百分比，无确定进度时显示“处理中”；暂停/失败显示相应文字或状态标识。缩略入口不同时展示所有任务，不重复数字和图标，也不嵌入关闭、暂停或取消按钮。

悬停或键盘进入后沿用现有侧栏展开行为，恢复 D25/D50 的完整任务列表与全部控件；离开后回到同一个底部汇总入口，不丢进度、滚动位置或当前任务。数量来自实际可见任务，关闭/隐藏后不计数，数量增加不增加占位高度。异常数量与原因包含在完整提示及读屏名称中；存在失败时用清晰错误标识辅助数量，不能仅依赖颜色。

无任务时隐藏汇总入口，设备与设置仍固定。短窗口将导航独立滚动以保留这个入口及固定底部控件，不把单个入口挤出窗口。图内绝对位置是示意，实施按固定底部区域及安全间距锚定；不把它重新排到工作区选择器下方。

### 逐字稿编辑（第十一轮）

D52 补充会议详情“逐字稿”标签的页内编辑状态，继承 D23 的详情标题、唯一顶部导出入口和固定底部播放器，以及 D25 的当前工作区选择器。逐字稿占满详情阅读区，不另设空白右栏。正文按后端当前逐字稿的段落 ID 显示，沿用 D11 的说话人头像、名称与时间行，下方是按实际文本自动高度的多行纯文本输入框；不套用笔记的 Markdown/富文本工具栏，不提供新增/删除段落、编辑时间或逐句保存按钮。

编辑入口沿用真实条件：会议已结束、有可编辑段落、没有正在精修；已精修时在当前精修逐句版本编辑，不在历史原始版本编辑。无时间戳的“精修全文”不提供逐句编辑。时间和说话人属于本次编辑的只读上下文；独立说话人改名能力沿用原流程，不混入文本保存请求。每段最大长度沿用实际 4000 字符约束。

取消/保存沿用 D37/D38 的 36px 图标按钮与读屏提示，不使用大型文字按钮。非聚焦段落用轻底色与细边，只有当前输入框强调边框；不把每句包装为带大量留白的大卡片。点击“编辑”后焦点进入首段输入框。标签行右侧统一显示状态与“取消”“保存”，输入框聚焦时用清晰细边强调；示例第三段显示“已修改”。版本选择在编辑中锁定，不允许切换到另一版本后把修改写错；精修和翻译入口收起。搜索沿用现有入口与筛选能力，筛选或切换标签不清空草稿，保存仍覆盖本次所有实际修改过的段落；点击输入文本不能触发音频跳转，时间戳定位沿用原能力。

| 状态             | 视觉与操作                                           | 数据边界                                           |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------- |
| 进入编辑，未修改 | “未修改”，统一取消/保存位置不移动                    | 不新增自动保存；无变化保存直接退出，不伪造写入成功 |
| 已修改           | “已修改 · 尚未保存”，输入框保留草稿                  | 只提交实际改动段落，保留段落 ID、时间及说话人      |
| 正在保存         | “正在保存…”＋忙碌标识，暂时禁用重复保存和取消        | 等待真实保存结果，不提前显示成功或清空可恢复草稿   |
| 保存成功         | 返回阅读态，沿用成功消息“字幕已保存”与已保存状态     | 重新展示后端选定的当前用户版本，不误报为重新精修   |
| 保存失败         | “保存失败，修改仍保留”，保存位置变为“重试”           | 留在编辑态并保留输入；桥接不可用时也不得丢草稿     |
| 段落为空         | 对应输入框显示错误边框及“字幕内容不能为空”，定位该段 | 本次不提交，保留其他段落修改；纯空白也按空内容处理 |
| 取消             | 退出编辑，恢复已保存文本                             | 沿用现有取消语义，只丢弃本次未保存的文本修改       |

播放器继续可用，不随正文滚动；详情顶部导出复用已保存内容，不把未提交草稿当作可导出的版本。翻译行如存在仍为只读，不能暗示人工修改已经重新翻译。后台刷新采用同一份编辑草稿，不吞掉用户输入、选区或焦点。新版 D52 展示五段紧凑逐句输入与“已修改”状态，其余状态复用 D39 的视觉规范与上表；保存中、失败重试及桥接缺失保留草稿等新视觉契约仍需实施，现有代码的保存处理不能直接标记为全部满足。

## 会议纪要阅读与重新生成（第六轮）

D23 只在选中“会议纪要”标签时使用单一阅读区：移除右侧“纪要模型 / 重新生成 / 导出与分享 / 会议纪要已生成”整列，正文占用释放的空间并保持阅读内边距。笔记标签的纪要预览仍按 D10、D37/D38 保留；两种布局对应不同标签，不互相覆盖。

纪要标题左侧为“会议纪要”和“AI 生成，请核对。”，右侧同一行依次为 **编辑、复制、重新生成**。生成时间与“已保存”放在标题附近作为辅助信息，不单独占用侧栏。底部播放条继续固定在详情主区；长纪要在正文区滚动，动作和播放控件保持可用。

详情顶部保留唯一的 **导出** 下拉按钮，笔记、逐字稿和纪要共用 D12 的导出流程。“会议纪要”标签打开该入口时默认选择纪要内容；用户仍可选择实际支持的其他内容与格式。纪要正文不另设导出按钮，不新增独立导出页面。纪要模型仅在设置的“AI 功能 → 会议纪要”中配置，阅读页不设常驻模型按钮。

D42 展示点击“重新生成”后，缺少可用内置模型的就地反馈。提示放在纪要标题与正文之间，配置动作为 **配置纪要模型**，打开已有纪要服务配置窗口（D15/D36），对应设置中的“AI 功能 → 会议纪要”。不新增一套配置表单，也不把用户丢到无关的模型库首页。配置问题提示使用可被读屏读取的状态区域；保留标题行操作与原有正文。

| 条件                                         | 提示文案                                                                               | 操作与结果                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 内置服务没有可用模型，或选定模型尚未下载完成 | **内置纪要模型未配置**；“请先选择并下载一个内置纪要模型，再重新生成。现有纪要仍保留。” | 配置纪要模型；已有可用内置模型仍遵循实际回退规则，不能仅因用户未手动选择就报错 |
| 在线服务缺少模型、必要 API 地址或密钥        | **纪要模型需要配置**；“请补全纪要服务的模型、API 地址和密钥，再重新生成。”             | 配置纪要模型；只要求当前供应商实际需要的字段，不要求内置模型填写密钥           |
| 在线鉴权失败 / 访问被拒绝                    | **纪要服务认证失败** / **纪要服务拒绝了请求**；按真实原因提示检查密钥或服务访问策略    | 配置纪要模型；保留原文，不把认证失败误报为尚未下载                             |
| AI 会议纪要功能已关闭                        | **会议纪要功能未开启**；“请先开启会议纪要功能，再重新生成。”                           | 配置纪要模型，定位同一功能的开关                                               |
| 配置已可用，生成处理中                       | “正在生成…”与真实任务阶段/进度                                                         | 防止重复提交；原纪要保留到新结果成功返回，不提前清空，不显示已成功             |
| 请求超时、网络或其他生成失败                 | “纪要生成失败，现有纪要仍保留。”与真实原因                                             | 允许重新生成；配置有效时不强制跳转配置                                         |

没有配置时先显示错误，不进入生成进度；配置保存后返回原会议，用户再次点击“重新生成”才开始请求。提示在当前会话内保持可见直至问题解决或用户关闭，不仅依赖会消失的 toast。尚未生成过纪要时复用同一提示和配置动作，正文改为空状态“尚未生成会议纪要”，按钮文案为“生成纪要”；不显示“现有纪要仍保留”。只在新结果成功返回并保存后替换旧纪要并显示成功状态。

这一节是新增设计目标。已有左下配置任务卡和旧 D23 运行截图不代表 D42 或新阅读布局已经实现。此前 [实现图册清单](design-manifest.md) 中 D23 的捕获结果对应旧版设计，新 D23 与 D42 均需重新接手和验收。

桌面引导顺序统一为 **语言 → 权限 → 模型与存储 → AI 功能 → 手机连接**。独立功能演示已按用户要求移除，D35仅为历史图；D27/D40的卡内预览仍保留。

配置弹窗复用真实供应商、模型、条件API地址/密钥、本地下载与原有安全存储；切换供应商保留各自草稿，未安装或缺少必需字段不能冒充已就绪。功能开关独立，原有配置字段、持久化及服务接口不变。

| 模式          | 触发和演示顺序                                                     | 写入笔记的时机                     |
| ------------- | ------------------------------------------------------------------ | ---------------------------------- |
| 关闭          | 关闭对应开关 → 停止/清空该功能预览 → 说明未开启                    | 不写入，两个功能的开关独立         |
| 手动 `quiet`  | 点击请求 AI 建议 → 分析 → 展示建议与“加入笔记 / 忽略”              | 用户点击加入；忽略后笔记不变       |

| 主动 `auto`   | 获取建议 → 用户输入时暂存 → 停笔后追加                             | 自动追加，无虚构“采纳 / 忽略”步骤  |

建议出现/消失使用 120–180ms 短淡入；正式笔记在真实写入对应的状态点一次追加，用户正在输入时不移动光标。会后纪要由任务态转入结果态，不逐字打字、不无故闪回骨架、不把进度条放进正文。切换主动性重置该模式演示，关闭开关停止演示；降低动态效果时直接显示状态。引导预览是样例，不调用真实录音、模型请求或保存接口。本轮交付静态分镜与交互约定，应用动画实现单独验收。

| 阶段                         | 桌面显示                                                      | 动作与结果                                                          |
| ---------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------- |
| 服务开启、无设备（D47）      | 等待设备连接；空设备列表；连接新设备                          | 同一局域网提示；无活动配对会话时不提前显示过期二维码                |
| 手机主动搜索/发现电脑（D48） | 自动打开一个“连接新设备”弹窗，二维码、6 位配对码、倒计时      | “等待手机提交配对请求…”；尚不知道请求设备名，不显示允许连接或已连接 |
| 手机提交配对请求（D49）      | 同一弹窗增加真实设备名、8 位大写十六进制校验词、拒绝/允许连接 | 核对手机与电脑显示的校验词；电脑确认后才建立信任                    |
| 允许连接成功                 | 关闭弹窗并更新真实已信任/已连接状态                           | 允许动作提交失败或尚无真实连接时不能提前把侧栏变绿                  |
| 拒绝、关闭或取消配对         | 结束当前请求和会话，原会议页面保持                            | 不自动重试、不建立信任；Esc 与关闭同取消语义                        |
| 配对码过期                   | “配对码已过期，请重新显示配对码。”；重新配对                  | 旧二维码/码停止可用，复制禁用，创建新会话后恢复倒计时               |
| 服务关闭或启动失败           | 服务已关闭/真实错误原因                                       | 保留开启服务或重试入口；不生成貌似有效的配对凭证                    |

二维码与配对码是示例，D48/D49 的 482 619 与 01:42 不代表有效凭证。校验词示例 **A7C92E4B** 与 6 位配对码是两个不同值；旧 D18/D31 的“青松 · 白云”只是历史示意，实施以真实 8 位十六进制值为准。画板不新增自动批准、账号登录或云端发现能力。

触发依据 [手机连接前端](../../frontend/mobile-connection.js) 的 mobile.discovered → pair 与 approval 状态，以及 [局域网服务](../../electron/mobile-server.js) 的 /identity 与 /pair。搜索只触发配对提示，不代表认证；服务已有发现通知限流，前端已有弹窗/创建中去重，连续发现不叠加多个窗口。请求到达时在同一弹窗内更新，不另叠审批窗口；已有手机审批处理中按实际串行限制提示。保留原页面、编辑草稿和任务状态，不因配对自动跳页或结束录音。

本轮新增画板是接手基准，现有会议/设备代码或历史运行截图不等于新菜单、批量入口、反馈和各配对状态均已验收。
