# Brevia 新设计语言

2026-10-12 · 设计提案 · 桌面与手机

## 设计主张

界面像一份干净的会议文档：导航负责找内容，正文负责阅读，控制条负责录音。用细线与留白分区，以黑色按钮明确下一步。替换旧方案的紫色主色、渐变、玻璃、厚阴影、大圆角和叠套卡片。

保留 Brevia 名称及现有产品能力。参考 yovoice 的视觉语法，不迁移它的语音合成、音色创作或音乐功能。

## 布局与组件

桌面设计源画布为 1440 × 900，默认窗口等比例缩小至 1280 × 800，统一采用 8/9（约 88.9%）缩放。下述桌面字号、间距和组件尺寸均为源画布单位，显示时一起缩小：主侧栏 272 → 约 242px，实时收起 64 → 约 57px，16px 正文 → 约 14.2px。原生标题栏按系统尺寸呈现。鼠标悬停或键盘焦点进入侧栏时展开，离开后收起，沿用现有行为。收起时隐藏工作区与任务卡片，存在任务时保留进度指示；展开后在侧栏底部显示任务堆叠。页面内边距 32–40。内容最大阅读宽度 760；双列任务由内容决定比例，笔记与转写可为 50:50，准备与选项可为 65:35。小窗口先收起次要列，主任务保持可读。

手机参考 390 × 844 pt / Android 412 × 915 dp，验证下限 360 宽。页面内边距 24，小屏不低于 20；安全区属于系统。一级底栏仅会议、连接、设置，进入会议或二级设置后移除。录音条固定在安全区上方，正文底部保留足够滚动空间。

间距 4 / 8 / 12 / 16 / 24 / 32 / 48。控件圆角 8，弹层 12；手机底部弹层可用 16 并保留系统手势。列表用分隔线，无每行阴影。图标使用同一套 1.5–1.75 线宽图形，20–24 视觉尺寸，不用 emoji 代替操作图标。

桌面按钮高 40–44，手机主按钮高 52；手机所有触控区域至少 48 × 48。每个任务区一个主要按钮，次要动作浅色描边，危险动作红色文字。正文和占位文字对比度目标至少 4.5:1。焦点用 2px 明确轮廓，键盘可见，选中不只靠颜色。

字段标签始终位于输入上方。错误就地说明问题和修复操作，保留已有输入。菜单用白底、细边、轻微层级阴影；只有弹层需要阴影。确认写明对象与后果，默认焦点在取消。长设置改为分组页面，减少反复弹窗。

## 引导

桌面沿用现有流程：语言 → 权限 → 模型与存储 → AI 功能 → 手机连接 → 功能演示。D03 是同一“模型与存储”步骤的保存位置展开态，D04 是模型列表主体；不拆分模型与存储；手机连接为现有的可跳过步骤。左侧固定品牌与步骤，右侧实际操作保持标题和动作对齐。首次功能演示展示真实转写/笔记布局，支持跳过。

语言从系统预选，支持全部 8 种现有语言：简体中文（zh）、English（en）、Español（es）、日本語（ja）、한국어（ko）、Français（fr）、Deutsch（de）、Русский（ru）。桌面引导显示这 8 项；手机语言设置另外保留“跟随系统”。麦克风说明用途，系统音频明确可选；拒绝某项权限不阻断不依赖它的录音方式。

模型选择沿用平台过滤后的现有模型列表，使用多选复选框，不按能力拆成下载包。macOS 示例为 Fun-ASR-Nano（1.56 GiB）、Qwen3-ASR 0.6B 8bit（0.94 GiB）、Parakeet TDT 0.6B v3（2.34 GiB）；Windows/Linux 名称和大小读取现有清单，不能硬编码此 macOS 示例。中文默认推荐 Fun-ASR，日/韩默认推荐 Qwen，英语及其他现有西方语言默认推荐 Parakeet。已安装模型仍可选择，但排除本次待下载和容量合计；尚无已安装模型且未选任何模型时沿用现有阻断提示。点击“下一步”保存路径、启动缺失模型下载并进入 AI 功能步骤，不等待下载完成；“稍后设置”、国内下载源及现有队列行为保持不变。“语音活动检测 / 说话人分离 / 声纹识别”为已随应用安装的说明，不是可选下载分组。存储包含模型、录音两个目录，沿用选择文件夹行为。

手机：欢迎 → 手机/电脑职责说明 → 按需授权提示 → 会议列表。首次录音才请求麦克风，首次扫码才请求相机，连接时申请所需网络权限。离线录音无需配对；手机无模型下载流程。连接成功不自动开启录音。

## 任务与状态

- 会议库使用可扫读的行式目录；搜索支持会议、字幕、说话人，空结果给清空搜索入口。工作区编辑留在相邻位置。
- 手机采集的会议在名称旁显示细线手机图标及“手机录音”来源标识；此标识与待转写、已整理、上传状态独立，不用于表示连接在线与否。
- 实时会议保留笔记与转写的独立阅读面。AI 建议必须显示采纳与忽略，不能伪装成已确认笔记。
- 当前实时会议不支持说话人识别。桌面、手机、功能演示、深色实时页面均只显示时间戳和转写正文，不显示姓名、头像、人数或说话人筛选。会后精修页面沿用现有说话人能力，不删除其身份标识。
- 手机会议底部使用三个纯图标按钮：暂停双竖线、重点书签、结束方块。按钮内及下方均无文字标签，触控区至少 48 × 48；暂停态使用继续播放三角形。为读屏提供“暂停录音 / 添加重点 / 结束会议”名称。重点表单提交、结束确认及中断恢复操作保留清晰文字；系统通知遵循原生组件。
- 录音、本地保存、传输、电脑转写分开表达。计时仅在真实采集开始后运行；静音不等于断线。
- 手机断线仍采集到本地时显示“正在录音 · 等待连接”，不把断线称为停止录音。恢复连接显示已确认的补传进度。
- 系统中断后显示已保存时长和缺口，用户决定继续；不声称中断期间仍有音频。
- 空间不足或写入失败时明确停止状态与保留结果，提供导出或管理存储入口；待上传录音不可自动清理。
- 手机结束先本地保存，待传与已传是不同结果。离线录音上传必须明确确认。
- 回看区分笔记、逐字稿、纪要、重点与音频。桌面可编辑笔记；手机电脑笔记只读，重点短备注独立保存。
- 精修与翻译允许保留旧内容并显示处理中/失败；错误不导致原始录音、转写或笔记消失。
- 导出按内容选择格式：我的笔记、会议纪要支持 Markdown / PDF / DOCX / TXT；逐字稿支持 SRT / Markdown / TXT / JSON；录音为 WAV。保留复制文字及当前已有分享渠道，系统分享使用原生入口。
- 配对要求电脑确认及校验词；二维码/PIN 是短时配对信息，不是长期凭据。取消信任不会删除会议副本。
- 当前跨网连接入口与能力仍保留在连接详情；本轮图优先展示扫码/PIN 主路径，不修改通信协议。
- 在线 AI 的准确说明为“相关文字按设置发送至所选服务商”；不使用无条件“所有数据都不出设备”。
- 删除区分本机副本、最近删除与永久删除，具体保留期限以实现为准，图不定义新期限。
- 系统更新按平台区分：Android 可走安装包下载/安装；iOS 按实际 App Store/TestFlight 分发路径说明。

## 现有任务卡片

D24 定义精修、纪要、翻译、模型下载队列、迷你会议、迷你播放、更新提示、AI 配置提醒和实时识别不可用提示；D25 定义进行中、暂停、完成、最小化、堆叠和下载失败；D26 展示侧栏收起与悬停展开的位置关系。卡片使用细边、轻底色、紧凑标题与真实进度，不引入任务中心或新状态。

卡片仍位于主侧栏底部，最新任务在前；后层只露标题，可点击或用键盘切换。沿用最小化“—”、还原“□”、关闭“×”。精修和纪要保留暂停/继续；翻译不新增暂停动作。下载保留整体及逐模型进度、暂停、取消、失败重试。迷你会议显示录音状态、计时与“继续会议”；迷你播放保留进度与播放/暂停。更新和配置提醒按现有能力显示按钮；实时识别不可用提示明确录音仍在保存，不使用虚假进度。

关闭语义沿用每类任务：关闭正在执行的精修会取消任务；关闭模型下载卡片只隐藏展示，活动下载继续。不能为了视觉统一而把所有关闭操作改成相同逻辑。

## 动态与适配

交互反馈 120–180ms，页面切换 180–220ms；使用短淡入，不持续漂浮或逐字打字。录音输入指示必须来源于实际信号。减少动态效果时立即更新或短淡入。流式文字不抢读屏焦点，也不打断用户已上滚的阅读。

深色保持同一结构与控件语义。系统大字下列表增高、正文滚动、按钮不截断；手机不压缩字体来塞入更多内容。iOS/Android 尊重各自返回、权限、分享和通知样式。

## 交付与验证边界

画板覆盖主页面、二级设置、引导、录音中断和危险操作；重复菜单及相同壳层的选项以此规范定义。画板是 AI 生成的静态设计概念，精确中文、控件尺寸、平台系统 UI 必须在实现时校准。此文件规定设计图的功能边界。实现验证另行记录；静态图不表示对应功能已通过测试。
