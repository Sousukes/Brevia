## 调整前复核：为什么仍与画板差距明显（2026-10-13）

本轮修改前的源码运行图仍有明显偏差。此前的改动校准了部分控件、行为和边界，但没有充分还原整页构图；运行检查通过和截图数量不能作为视觉完成的依据。该次仅复核和记录根因；后续实现见上方原生 1280×800 记录。

| 页面         | 画板视觉                                                                       | 当前运行图                                                                         | 仍需解决的问题                                                                                           |
| ------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| D07 开始会议 | 左侧单列宽字段，标题下有说明，右侧来源区有独立标题与说明；内容纵向展开         | 左侧工作区/语言及翻译/人数为双列紧凑表单，缺少标题说明，来源选项密度和按钮尺寸不同 | 重新按画板安排表单结构与纵向节奏；实际多出的模型和人数字段需纳入同一布局，不能仅为塞入屏幕改成另一种构图 |
| D13 设置总览 | 标题、说明、组标题、行名称与描述有清晰字号层级，组间有呼吸空间                 | 说明和行描述偏小，组间紧凑；关于/更新还保留行内旧按钮布局，图标视觉尺寸也不同      | 同时校准字号、字重、行高、图标、行高、组间距及右侧动作，而非只检查九个入口是否可见                       |
| D10 会议详情 | 会议标题与纪要标题有较接近的视觉分量；笔记正文有完整标题、段落、列表与分隔节奏 | 纪要栏标题仍明显偏小；现有截图中有逐字稿态与空笔记态，不能替代画板笔记态的正文验收 | 先用相同状态和可比较的样例内容核对正文与纪要，明确新增编辑/复制操作的占位，不用不同状态证明整页一致      |

对照原图：[D07](D07.png)、[D13](D13.png)、[D10](D10.png)。当前实现：[开始会议](implementation/desktop-prepare.png)、[设置](implementation/desktop-settings.png)、[详情笔记态](implementation/desktop-detail.png)、[详情逐字稿与纪要](implementation/desktop-detail-ready.png)。会议、路径、日期和模型数据不同本身不属于视觉缺陷。

根因：

1. **构图没有按页还原。** 保留了一些旧结构，再用 CSS 修补颜色、间距和按钮边界；结构变化会同时改变行宽、换行、留白和页面重心。
2. **尺寸缺少图像与实际页面之间的标定。** 文档规定逻辑画布 1440×900、默认 8/9 缩放，但本次读取的 D01-v2、D07、D10、D13、D27 PNG 实际为 1586×992，D02-v2 为 1584×993；部分图还有画板标题、模拟窗口边框和标题栏。像素尺寸差异不能直接证明缩放错误，也不能直接按图片像素填写 CSS。必须先定位应用内框，处理原生窗口差异，再建立一致的比较尺度。
3. **字体检查只做到基础一致。** 使用系统字体和检查 `fontFamily` 字符串，不等于核对实际中英文字形、字重、文字边界、行高和字号层级。图中的视觉大小与规范里的通用字号也没有逐页协调。
4. **新旧样式仍重复定义。** `tailwind.css`、`workspace-styles.css`、`detail-header.css` 与 `design-layout.css` 同时作用于页面；后者仍有多个 `#detail-view .notes`、准备页、设置导航及表单操作区规则。重复不必然是错误，但使最终效果难以由单一规则解释，需要核对最终计算样式并整理实际冲突。
5. **验收偏重可用性。** 底部按钮可见、没有溢出、操作及草稿保存正常，只证明功能与边界。此前未建立同状态、同尺度、可比较内容的逐页视觉对照。

后续还原须以画板确定构图和视觉比例，保留规范规定的真实功能及系统边界；先统一壳层与排版，再逐页处理结构，最后处理控件细节。引导整页容纳全部内容的要求继续有效，不能用缩小字号或压紧整页替代正确布局。未知字体和系统窗口差异应明确记录，不能写成“全部 1:1”。

## 执行与验收边界

- 当前唯一基准为 **1280×800 CSS 视口、100% 显示**；先前 1440×900 / 8/9 尺寸记录作为历史保留，不再指导实现。
- 引导页默认整页容纳所有内容，不滚动页面、不裁切底部操作。只在模型列表、演示正文等指定区域出现内容滚动；配对请求出现时，二维码、校验词、拒绝/允许和取消也必须同时可见。
- 复用现有接口、真实模型清单、下载队列、权限、路径、密钥保存、信任设备和会议数据，不改变协议或持久化字段。
- 保留八种语言和六步引导；实时会议不显示说话人身份，会后保留身份及人工编辑。
- 在线 AI 说明相关文字发送至所选服务商；安装二维码、临时配对二维码和 PIN 分开。
- 不照搬画板的示例日期、模型、容量、版本、二维码和验证码。不增加缺少接口支持的模型导入、模型更新、测试连接、存储配额等按钮。
- 删除、恢复、下载取消、任务关闭和离线录音确认上传继续使用既有语义。
- 不手动修改生成的 `frontend/styles.css`；需要更新时通过构建生成。
- 状态按具体证据更新。“已有运行对照”只表示已有截图及对应检查，不代表用户认可还原效果；异常状态、其他语言和平台的视觉验收分别记录。
