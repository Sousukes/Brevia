# Brevia 设计风格与页面构图

更新日期：2026-10-12。本文件描述界面应该呈现的视觉气质和页面结构。颜色、字体、尺寸及操作语义见[设计语言](design-language.md)，实施状态见[前端 UI 重构进度](frontend-ui-refactor-progress.md)。

## 当前风格

当前风格是简洁的文档式工作台：白色阅读面、浅灰导航、细线分区、克制的黑色主操作。视觉重心落在会议内容及下一步动作上，品牌通过字体、比例和一致的细节体现。

设计参考来自 yovoice 的工作台截图，借鉴其简洁语言；产品流程和能力仍由 Brevia 决定。桌面采用左导航、右内容，手机使用原生导航和触控结构。

旧的紫色主色、装饰渐变、玻璃浮层、厚阴影、大圆角外壳及嵌套卡片不再作为当前设计依据。状态色、原生系统界面和表示数值的进度/音量轨道可以保留各自必要的表达。

桌面画板保留 1440×900 源尺寸，应用按 8/9 显示为 1280×800。评审时先确认比例，不要因画板与截图的像素尺寸不同而给单个页面补第二次缩放。

## 桌面构图细节

### 导航与列表

常规侧栏源宽 272px，品牌、开始会议、导入、会议目录、工作区和底部设备/设置入口形成稳定顺序。选中项用轻底色和文字/图标强调，不另造彩色导航。

会议库保持行式目录，不改成同尺寸卡片网格。标题与标签靠左，处理状态和更多操作靠右。“手机录音”紧邻会议名称，使用矩形手机图标；不要与麦克风或电话听筒混用。

工作区编辑沿用新建、编辑、删除确认的既有动作。确认弹窗承载风险说明和取消/确认按钮，不把普通浏览步骤改成连续弹窗。

### 录音准备与导入

字段标签、输入起点和主动作对齐。采集来源用紧凑选项行，显示实际设备或连接状态。手机连接属于原有来源能力，不新增虚假的采集模式。

导入以真实文件选择或拖放为起点。占位框、已选文件、准备中和失败重试属于同一布局；错误说明不能遮住原有字段或清掉选择。

### 实时会议与任务区

仅实时会议自动收起主侧栏到源宽 64px，悬停或键盘焦点进入后恢复。详情页保持完整侧栏。收起时不挤压显示工作区和完整任务卡片，可保留任务进度提示。

笔记、字幕的标题、工具条、正文和底部控制条形成清晰层级。实时字幕只显示时间戳与正文；AI 建议显示采纳/忽略。不要用说话人头像或虚假人物让页面显得更丰富。

任务卡片用小型类型图标、紧凑标题、阶段说明、细进度条和操作按钮。暂停状态配文字及语义点；最小化后保留还原入口。后层任务支持点击和键盘切换，不盖住设备和设置入口。

### 设置与引导

设置总览按基础设置、会议与 AI、设备与数据组织。连续设置页有明确当前位置，模型库、声纹、设备和存储使用实际数据。

首次引导顺序固定为：语言 → 权限 → 模型与存储 → AI 功能 → 手机连接 → 功能演示。模型与存储属于同一步；手机连接可跳过。

AI 页的两个功能卡片表达独立设置，右侧预览只解释效果。配置弹窗只包含所选服务真正需要的字段。本地模型与在线供应商配置分别使用 D36、D30。

手机安装区域分别说明 Android APK 和 iPhone TestFlight；配对区域展示真实短期二维码、PIN 和电脑确认状态，不借用安装卡片表示连接成功。

功能演示用五步导航和直接阅读区，不能重新引入旧版缩小应用窗口、模拟标题栏或可触发录音的样例控件。

## 手机构图细节

一级会议页顶部保留品牌、新录音和搜索，正文为会议列表；新录音动作不在底部重复放置。进入会议、回看或二级设置后，按现有导航移除一级底栏。

准备页为单列真实字段。离线/已连接模式由既有连接状态决定；工作区、模型和翻译仅在既有条件满足时显示。人数用于会后整理，不表示实时识别说话人。

会议页把录音、本地保存、上传和电脑处理分别说明。暂停/继续、重点、结束只用图标按钮，保留 Tooltip 和可访问名称。结束沿用直接保存并进入结果页的行为，不因 M09 的概念示意添加新的确认步骤。

重点弹层显示打开时的时间点，备注可选、最多 200 字。语言、外观是连续二级页；说明和隐私页面优先保证长文本阅读。

首次引导有三个页面：欢迎、手机与电脑职责说明、按需授权提示。引导只说明用途，系统权限在首次使用对应能力时请求。

## 交互与质感

深浅色使用相同的空间结构、内容层级和动作。hover、focus、selected、disabled、pending、error 必须能分辨；表单标签始终可见，失败后保留输入。

页面切换和操作反馈保持短而稳定，尊重减少动态效果设置。不要添加持续漂浮、装饰性粒子、流式文字逐字动画或强行滚到最底部。

手机尊重原生返回、安全区、系统文字大小、权限、分享和通知。桌面使用真实窗口标题栏和原生文件选择器；设计图不能替代系统 UI。

## 评审与扩展

1. 先核对真实能力、平台和当前状态，再选择对应有效画板。
2. 比较整体比例、标题与动作位置、阅读面、控件形态，再核对颜色与细节。
3. 用真实文案检查长标题、八语切换、浅/深色、空/忙碌/失败状态；手机同时检查小屏和系统大字。
4. 没有对应画板的页面或状态先补图和功能边界，再复用既有组件实现。
5. 更新运行截图和验证记录，写明完成项与仍需真机确认的部分。

实际页面可从[运行对照](redesign-2026-10-12/implementation.md)打开。静态生成图中的局部中文、图标及示例数据可能有偏差，修正依据见完整规范；不能把这些偏差变成新的产品功能。
